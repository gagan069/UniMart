Page 06 // State Engineering

Master State Architecture Matrix

Architectural decision rationale comparing Context API vs. Redux Toolkit vs. Local State.

State Tool Data Stored Frequency Architectural Justification (Viva Point) Key Implementation Files
React Router URL routes ('/', '*'), layout outlet Low Enables browser history (back/forward), shareable deep links, and prevents full page refreshes. main.jsx, App.jsx, Layout.jsx
Context API AuthContext (user session), ThemeContext Infrequent Perfect for app-wide broadcast settings. Eliminates prop drilling with zero boilerplate. AuthContext.jsx, ThemeContext.jsx
Redux Toolkit listingsSlice (catalog), wishlistSlice High / Async Manages multi-state async lifecycles (pending, fulfilled, rejected) via createAsyncThunk. store.js, listingsSlice.js, wishlistSlice.js
Local State Sell modal inputs, search text, active category pill Per Keystroke Keeps ephemeral form data isolated. Prevents re-rendering the entire app on every keystroke. Dashboard.jsx, LoginPage.jsx
lightbulb Viva Defense Summary: Why Not Everything in Redux?

Putting every temporary input into Redux causes unnecessary action dispatches and forces unrelated components to re-evaluate. Conversely, putting the async catalog in Context requires custom dispatch reducers without Redux DevTools observability. UNIMART strictly chooses the right tool for each state category.

export const fetchListings = createAsyncThunk( 'listings/fetchListings', async () => { await new Promise(r => setTimeout(r, 500)); return mockListings; } ); // ExtraReducers State Machine extraReducers: (builder) => { builder .addCase(fetchListings.pending, (state) => { state.status = 'loading'; }) .addCase(fetchListings.fulfilled, (state, action) => { state.status = 'succeeded'; state.items = action.payload; }) .addCase(fetchListings.rejected, (state, action) => { state.status = 'failed'; state.error = action.error.message; }); }
favorite Duplicate-Proof Wishlist (wishlistSlice.js)
const wishlistSlice = createSlice({ name: 'wishlist', initialState: { items: [] }, reducers: { addToWishlist: (state, action) => { // Prevents duplicate entries const exists = state.items.some(i => i.id === action.payload.id); if (!exists) state.items.push(action.payload); }, removeFromWishlist: (state, action) => { state.items = state.items.filter(i => i.id !== action.payload); }, clearWishlist: (state) => { state.items = []; } } });

Page 10 // Security & RBAC

Role-Based Access Control (RBAC) & Permissions

Granular authorization protecting listings, admin capabilities, and student data integrity.

shield_person Admin Role
  • Moderation Privileges: Can edit, delete, or mark any campus listing as sold.
  • Platform Oversight: Access to Admin review tools and policy enforcement.
  • Seeded Account: admin@chitkara.edu.in
school Student Role
  • Self-Ownership Enforcement: Students can ONLY edit or delete listings where seller_id === user.id.
  • Listing Creation: Can upload items with photos, prices, and meetup notes.
  • Domain Restriction: Verified college email required.
visibility Guest Role
  • Read-Only Access: Can browse and search the public catalog without logging in.
  • Blocked Actions: Cannot post listings, chat with sellers, or access wishlists.
  • Instant Login Prompt: Guided to Google SSO or Email Sign-in.

export function canManageListing(user, listing) { if (!user || !listing) return false; if (isAdmin(user)) return true; // Admin can moderate all return Boolean(listing.seller_id && user.id && listing.seller_id === user.id); }
